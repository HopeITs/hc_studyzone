# قائمة فحص يدوي قبل إطلاق النظام المالي (Phase 7)

> جهّز أولاً: `php artisan db:seed --class=FinancialDemoSeeder` على قاعدة بيانات تجريبية (ليست الحقيقية!).
> المستخدمون التجريبيون (كلمة السر لكلهم: `password`):
> - أدمن عام: `admin.demo@sz.com` ← **هو الوحيد الذي يصل للنظام المالي**
> - مدير مركز: `manager.demo@sz.com` ← للتأكد من الحجب فقط
> - كاشير: `cashier.demo@sz.com` ← للتأكد من الحجب فقط

ضع ✅ أو ❌ أمام كل بند. أي ❌ = لا نطلق قبل إصلاحه.

## 1. حصر النظام المالي بالمدير العام
في هذا الإصدار **المدير العام فقط** يرى أو يستخدم أي شيء مالي (نقطة البيع، الفواتير، المصروفات، المخزون، الورديات، التقرير المالي، ودجتات الأرقام المالية في الرئيسية، وروابط الطباعة والإيصالات).
جرّب بكل من `manager.demo@sz.com` (مدير مركز) و `cashier.demo@sz.com` (كاشير)، وأيضًا بمستخدم مدير مدينة وملاحِظ إن توفّرا:
- [ ] لا يظهر في القائمة الجانبية أي عنصر مالي (نقطة البيع، الفواتير، المصروفات، المخزون، الورديات، التقرير المالي).
- [ ] الصفحة الرئيسية لا تعرض أي ودجت مالي (إيرادات، مبيعات حسب الفئة، إحصاءات مالية).
- [ ] فتح الروابط المباشرة لكل شاشة مالية يُرفض (403 أو لا يظهر شيء).
- [ ] رابط طباعة فاتورة (`/invoices/{id}/print`) ورابط تقرير وردية وإيصال مصروف → 403، حتى لو كانت من مركزهم.
- [ ] باقي النظام (الطلاب، الدخول، إلخ) يعمل لهم كالمعتاد دون تغيير.

## 2. الصلاحيات — الأدمن العام
سجّل دخول بـ `admin.demo@sz.com`:
- [ ] يرى كل الشاشات المالية والتقارير لكل المراكز، ويستطيع التبديل بين المراكز في نقطة البيع.
- [ ] يستطيع تعديل الأسعار (خدمات + أسعار المراكز) وقفل/فتح الأشهر وإدارة المستخدمين.

## 3. قفل الشهر
البيانات التجريبية فيها شهر مقفل (سبتمبر 2026). جرّب كأدمن عام:
- [ ] إنشاء فاتورة يدوية بتاريخ اليوم بعد قفل الشهر الحالي (اقفل الشهر الحالي مؤقتًا) → مرفوض برسالة واضحة، ثم افتح الشهر مرة أخرى.
- [ ] تحصيل فاتورة غير مدفوعة تاريخها في الشهر المقفل → مرفوض.
- [ ] إلغاء فاتورة في الشهر المقفل → مرفوض.
- [ ] تعديل/حذف مصروف تاريخه في الشهر المقفل → الأزرار مخفية، والحذف الجماعي لا يختار صفوف الشهر المقفل.
- [ ] "إضافة شراء" أو "جرد" للمخزون والشهر الحالي مقفل → مرفوض.
- [ ] فتح وردية والشهر الحالي مقفل → مرفوض.
- [ ] بعد فك القفل، كل العمليات السابقة تعمل طبيعيًا.

## 4. نقطة البيع والورديات
- [ ] لا يمكن البيع بدون وردية مفتوحة (رسالة واضحة).
- [ ] فاتورة بها خدمة + صنف مخزون: الإجمالي صحيح، ورصيد الصنف نقص بالكمية الصحيحة.
- [ ] خصم أكبر من الإجمالي لا يعطي إجماليًا بالسالب.
- [ ] إغلاق الوردية: النقدية المتوقعة = رصيد الافتتاح + المبيعات النقدية − المصروفات، وأي فرق يتطلب ملاحظة.
- [ ] تقرير الوردية يُطبع وأرقامه مطابقة.
- [ ] إلغاء فاتورة مدفوعة (كأدمن) يرجّع المخزون ويظهر عكس الحركة.

## 5. التقارير
- [ ] التقرير المالي الموحد: إيرادات + مصروفات + الصافي لفترة محددة تطابق مجموع الفواتير المدفوعة والمصروفات يدويًا (خذ يومًا واحدًا واحسبه يدويًا).
- [ ] الفواتير الملغاة وغير المدفوعة لا تدخل في الإيراد.

## 6. سجل النشاط (كأدمن)
افتح سجل النشاط وتأكد أن كل عملية من هذه تركت أثرًا باسم المستخدم الصحيح:
- [ ] إنشاء فاتورة، تعديل فاتورة، إلغاء فاتورة.
- [ ] إضافة/تعديل/حذف مصروف (وحذف المصروف يسجّل أيضًا حذف حركات المخزون المرتبطة).
- [ ] حركة مخزون (شراء/بيع/جرد).
- [ ] فتح وإغلاق وردية.

## 7. أمان سريع
- [ ] رابط إيصال مصروف لا يفتح بدون تسجيل دخول، ولا يفتحه أي مستخدم غير المدير العام.
- [ ] طباعة فاتورة برقم فاتورة مركز/مدينة أخرى (غيّر الرقم في الرابط) → مرفوض لغير الأدمن.
- [ ] مستخدم معطَّل (is_active = لا) لا يستطيع الدخول ولا الطباعة.

## 8. عام
- [ ] كل الشاشات الجديدة سليمة بالعربية (RTL) وعلى الموبايل، والنصوص مترجمة (لا مفاتيح خام مثل general.xxx).
- [ ] لا أخطاء في `storage/logs/laravel.log` أثناء الجولة.
